# daily-drill — 일일 학습 루틴 (2트랙)

> 안키처럼 매일 1회. **논점 frontmatter(#19-B 정본) → 오늘 논점 선정(2트랙) → 트랙별 출제·채점 → 약점 복습등록**.
>
> **과목 풀네임 필수**: 민사소송법·민사집행법·형사소송법·형법총론·형법각론·행정법·헌법·민법. 약칭(민소법·민집법 등) 사용 금지(#50-B, #51).
>
> **2트랙 모델 (2026-06-20 개편, 2026-06-30 v2 정합):**
> - **진도 트랙 = 나가고 있는 논점(회독 0·진행 중) → 선택형(객관식) 바로.** 객관식은 한 번 밀리면 계속 밀리므로 진도와 함께 즉시 정착시킨다. 논점이 아직 안 끝났으니 사례형은 보류(지식 정착·retention 단계).
> - **복습·심화 트랙 = 이미 나간 논점(회독 ≥ 1) → 사례노트(`sync/위키/사례/{과목}/`) 출제·채점 소스 우선, 사례형(포섭 검토 강화) + SRS 선택형 복습.** 논점이 통합된 뒤라야 쟁점추출·포섭이 가능하므로 1회독 완료 후 사례형. 약점은 선택형으로 retention 점검(응용·포섭 단계).
>
> 소스 근거주의(#1): 모든 문제·정답은 사용자 워크스페이스 소스(카드 TSV·위키 원문·교재 OCR)에서만 만든다. 외부지식·추측 출제 금지(#2).

## Phase 0 — 오늘 세션 구성 (먼저 1회)

```powershell
python .agent/skills/daily-drill/scripts/build_session.py    # 기본 --n 6 (2026-07-06 확정)
# 특정 과목만:  --subject 민법
```

산출:
- `.agent/state/drill_session.json` (기계용: `진도논점`·`복습논점`[각 논점에 `사례문제`=사례노트/진도매핑 조인 결과]·소스후보·`복습due`·`사례대기`)
- `6.진도관리/오늘_드릴.md` (사람용 브리프 — 진도/복습 2섹션)

**트랙 분리 규칙(스크립트 내장):**
- **진도 트랙**(선택형): 논점 frontmatter 회독=0이면서 진행 흔적이 있는 논점 — 방학목표(`방학_논점`) 우선, 그다음 선택>0·사례>0·최근드릴 있는 논점(=시작했지만 1회독 미완). 진행 중 논점이 식별 안 되면 진도 트랙은 비우고 브리프에 고지한다(board_server_v2/진도보드.base에서 현재 진도 논점을 표시하면 자동 구성).
- **복습·심화 트랙**(사례형+SRS): 회독 ≥ 1 또는 약점 논점 — **3계층 정원제(2026-07-07, 잠식 없이 모두 충족)**: ①약점 ≤4(초과분은 SRS 익일 순환) ②**목표 집합** 3('하고 있는 것' = 진도보드_목표.json 방학_단원 ∪ 내신_학기별 현재 학기) ③**전체 롤링** 2(목표 밖 최구드릴 순 — 유지 리허설) = 최대 9논점, 후보 없는 계층은 자동 축소(상호 잠식 없음). "가볍게"(n<5)면 2+2+1. 각 계층 내에서는 최근드릴 오래된 순·선택 적은 순. 브리프·대시보드에 티어 표기. 근거: 목표 집합은 인접·혼동 가능 논점이라 복습을 여기서 뽑으면 변별 대비 인터리빙이 자연 발생(검증된 조건부 이점) + successive relearning(현행 단원 기준 도달 후 간격 재학습); 전체 롤링은 재학습 절약 원리상 소량으로 충분하고 장기 유지 주 담당은 안키 FSRS. **비율(2/3·1슬롯)은 운영 설정값**. 해당 논점에 사례노트(`sync/위키/사례/{과목}/`)가 있으면 우선 출제 소스로 사용.
- 각 트랙 최대 `--n`개.

스크립트는 **선정·소스 포인터까지만** 한다. 문제 생성·채점은 아래에서 Claude가 한다(소스를 직접 읽고 출제 → #1 준수).

**복습 3루프(#52-C)·채점관(#52-B) 운영:**
- **증량(2026-07-04, 2026-07-06 일 기본 증량 확정)**: 평시 기본 = **`--n 6`(논점 6) + 논점당 문항 8 + 복습 사례 3건**. 사용자가 "증량/많이/빡세게" 하면 논점당 문항 10, 복습 사례 4건(수치 지정 시 그대로). 반대로 "가볍게"면 `--n 2`·문항 3~4·사례 1건. (문항수·사례건수는 운영 설정값 — 학습과학 근거는 출제 구조 3스텝에만 해당.)
- **시험모드(2026-07-04)**: build_session이 learning.json `exams`에서 최근접 시험 D-21 이내면 자동 가동 — 브리프에 `시험모드: {시험} D-n` 표기, subjects가 과목 목록이면 그 과목 논점을 트랙 선두 배치. **D-14 이내엔 `사례억제` 플래그** → Phase 2-A(사례형)를 생략하고 2-B 선택형 + 찌라시(시험장 압축) 위주로 돈다(사례는 사용자가 명시 요청 시만). 시험 등록/해제는 learning.json exams 편집(또는 board_server_v2 /api/exams).
- **L0 필수복습(2026-07-06 확대)**: **어제·오늘 '본' 논점은 다음 세션에서 복습 필수(생략 금지)**. '본' 것의 원천 3종 — ①수업 지정(`--today` → frontmatter `최근수업`) ②드릴 출제(drill_log → `최근드릴`) ③**진도보드 체크(서버 /api/bump·보드 저장 시 `최근체크` 자동 스탬프)**. build_session이 세 날짜 중 하나라도 오늘·어제면 필수복습 트랙에 넣고 원천을 표기한다. 논점당 선택형 4~5문, 이후 SRS(L2)로 흡수. 학기중 기본 루프.
- **G0 자가채점("번호만")**: 요청 시(또는 토큰 부족) 문제 본문을 생성하지 않고 **선정 논점 + 문제 번호·소스 위치**(예: 신민사법선택형 p.312 문12·사례노트 [[제목]])만 브리프에 출력. 사용자가 풀고 책 해설로 직접 채점 → `--mc 9/12`·약점명만 보고하면 Phase 3에 그대로 기록.
- **사례형 채점 라우팅**: 기본 G2 초벌(Sonnet 서브에이전트, 포섭격자 셀 대조 O/△/X+갭목록) → `애매` 플래그·실전답안·"종심" 요청만 G3(세션 모델)로 에스컬레이션(#52-B).

진도 입력원(v2 정본, #19-B): **논점 frontmatter** = `sync/위키/{과목}/{쟁점}.md`(회독·선택·사례·약점·진도 필드). build_session.py는 이 frontmatter를 읽어 트랙을 분류한다. 인터페이스 병존: `6.진도관리/board_server_v2.py`(HTML 데스크톱 입력) + `sync/위키/진도보드.base`(Bases 열람) — 둘 다 같은 frontmatter 읽고 씀. `progress.json`·`진도_현황.json`·`진도_state.json`은 구 v1 snapshot이며 정본 아님 — 참조 금지. frontmatter가 비어 있으면 회독 0으로 간주하고 진행(브리프에 고지).

## Phase 1 — 진도 트랙: 선택형 바로 (나가고 있는 논점, 회독 0·진행 중)

핵심: 막 배우는/배우는 중인 논점을 **선택형(객관식)으로 즉시 리뷰**해 조문·판례 결론·개념을 정착시킨다. **사용자가 답안을 길게 쓰지 않게 한다.** Claude가 문항+정답키+근거를 먼저 확정하고, 사용자는 고른 번호만 한 줄로 주면 Claude가 정답키와 **진리값(O/X) 대조 → 즉시 점수**. (속도 최우선)

### 출제
1. `drill_session.json`의 각 `진도논점`의 `카드파일`/`위키`/`페이지후보`를 **Read로 직접 읽는다**.
2. 카드 TSV에서 출제 변환 — **축별 출제 단위 규칙(2026-07-04 확정, A안 강)**:
   - **요건·효과 축 = 세트 단위 필수.** 요건 1개만 잘라 OX·단일 빈칸으로 내는 것 금지(파편 출제 — 요건 체계를 통으로 못 봄). 허용 유형:
     (a) **세트 열거 재생형** — "경개 성립요건 3가지는?" (구두/한 줄 답, G0 자가채점 친화, 사례형 목차 재생 직결)
     (b) **멀티 빈칸 클로즈** — 요건 전체 나열문에서 2~3곳 동시 빈칸(한 문항)
     (c) **침입형 선다** — "다음 중 ○○의 요건이 아닌 것은?" (전체 세트 + 변형 오답 1)
     (d) **미니사례 포섭형** — 3~4문장 사실관계 + "충족되지 않는 요건은?" (사례형·객관식 겸용, 가능하면 논점당 1문 포함)
     - 예외: 특정 요건 자체에 판례 해석 쟁점·함정이 있으면(예: 경개 '중요한 부분' 판단기준) 그 요건만 개별 출제 허용 — 근거 판례 명시.
     - 폴백(#1): 소스에 요건이 열거돼 있지 않은 논점(판례 나열형)은 이 유형을 생략한다. 억지 세트 생성 금지.
   - **판례 축 = 개별 OX·판시 고르기 유지.** `case_law`(사건명·쟁점·판시·결론) → 판례 결론 OX·판시 고르기. 변시 선택형 실제 형식(지문 정오 조합)과 일치하므로 개별 문항이 옳다.
   - `cloze`({{c1::}}) → 빈칸 4지선다. 단 그 빈칸이 요건 세트의 일부면 위 (b) 멀티 빈칸으로 승격해 세트로 묶는다.
3. 문항 수 기본 **논점당 8개**(2026-07-04 확정; 일 기본 `--n 6` 기준 진도 트랙 총 48 — 부담 시 사용자가 "가볍게"·수치 지정). 배분 가이드: 요건·효과 세트 2~3 + 판례 OX 4~5 + 미니사례 포섭형 1(소스 허용 시). 사용자가 "10개만" 등 지정하면 따른다.
3-B. **세션 구조 3스텝(2026-07-06, 근거 `9.작업중/클로드/조사보고_드릴출제구조_2026-07-06.md`)**:
   - **[1] 논점 선정 = 혼동 클러스터 우선**: 오늘의 논점 3개는 무관한 것보다 **서로 혼동 가능한 인접 논점**(같은 대분류·유사 법리 — 예: 경개↔준소비대차, 관습법상 법정지상권↔§366 법정지상권)으로 묶는 것을 우선한다(변별 대비 기제 — 인터리빙 이점은 혼동 가능 범주에서만 성립). build_session이 같은 대분류 후보를 우선 채움.
   - **[2] 논점별 블록(개념→응용)**: 논점당 5문 내외 — 요건·효과 세트(개념 선행) → 판례 OX 일부. 초심(회독0) 논점은 이 순서 엄수, **회독≥1 재출제 논점은 개념 세트를 1문으로 축소하고 응용 비중 확대**(expertise reversal — **단 이 축소는 선택형 개념 세트에만 적용. 사례형 모범답안 정독·구조 분석은 상급 단계까지 유지** — 비구조화 법적 추론에서는 역전 미발생, Nievelstein 2013).
   - **[3] 혼합 라운드**: 남은 문항(판례 OX·미니사례, 논점당 3문 내외)을 **논점 라벨 없이 선정 논점 전체를 섞어 무작위 배치** — "이 지문이 어느 논점 문제인지" 판별부터 답안의 일부(변시 실전 형식·문제유형→법리 연합 훈련·블록 학습착각 차단). 선정된 논점들이 전부 다른 대분류(혼동 소지 없음)면 라벨 판별 요구는 생략하고 셔플만 한다. **필수 조건 3(2026-07-07 검증조사)**: ⓐ**채점·피드백에서 문항별 논점명 반드시 명시**(범주 정보 미제공 시 인터리빙 이득 소멸 — Yan & Schuetze 2022) ⓑ**성취 게이트** — 블록 단계 정답률 과반 미달 논점은 혼합에서 제외하고 블록 형태로 재출제(저성취 상태의 순수 인터리빙은 해로움 — Hwang 2024) ⓒ라운드 종료 시 "혼합 라운드 정답률·지난 세션 대비" 1줄 표기(혼합 형식 기피·전략 이탈 방지 — Onan 2022).
4. **난이도 태그**(카드의 `난이도::A/B`)가 있으면 A(핵심) 우선.
5. **#51 A 카드 우선 출제**: `단계::` 태그(쟁점/규범/포섭/결론)·`증명책임::` 태그(원고/피고)가 붙은 카드가 있으면 해당 논점의 핵심 출제축으로 삼는다(예: 요건사실 고르기, 증명책임 귀속 OX). `카드검증: 완료` 마커가 없는 논점은 출제 전 "카드 미검증" 경고를 1줄 표기하고 가용 카드만 사용한다.

### 채점 (진리값 대조)
- 사용자가 `1① 2X 3② 4O 5③ 6①` 식으로 주면 → 정답키와 1:1 대조 → `맞 4 / 틀 2`, 틀린 문항만 근거 1줄로 짚는다.
- 사용자가 "채점" 또는 "정답 보여줘"만 하면 → 정답키 공개 + 사용자가 "3,5 틀림"처럼 알려주면 그 진리값만 반영.
- 점수 = 맞은수/총수. **소스 없는 정오 판정 금지**(#1·#2). 카드 자체가 `검증필요::사건번호`면 그 문항은 채점에서 제외하고 "검증보류" 표시.
- **세트 문항 부분점수(2026-07-04)**: 요건·효과 세트 문항(열거형·멀티 빈칸)은 정답키를 요건별 서브키(예: `6-1 구채무존재 / 6-2 신채무성립 / 6-3 중요부분변경`)로 분해해 `n/m`으로 채점한다. 총점 집계에는 세트=1문항으로 환산(n/m 비율). 약점 등록은 세트 전체가 아니라 **틀린 서브 요건 단위**로 한다(예: "경개-중요부분변경").

### 약점 포착
- 틀린 문항의 `주제::` 태그 → 약점 후보 목록에 모은다(예: "권리남용 요건", "사정변경 요건").
- 같은 주제 2회+ 반복 오답 → Phase 3에서 SRS 등록 + (선택) 안키 카드 후보 제안(card-wiki-pipeline §8 note_key 준수).
- **고확신 오답 우선(P0-3, 2026-07-14)**: 확신(`!`)했는데 틀린 문항은 메타인지 오류(잘못 알고 확신)라 교정 우선순위가 높다 → Phase 3에서 `--weak "!사정변경 요건"`처럼 **접두 `!`**로 넘기면 SRS `priority high`로 등록된다. 불확신(`?`) 오답은 통상 우선순위.

## Phase 2 — 복습·심화 트랙: 사례형(포섭 검토) + SRS 선택형 (이미 나간 논점, 회독 ≥ 1)

이미 1회독+ 끝낸 논점은 **사례노트(`sync/위키/사례/{과목}/`)를 우선 소스로 사례형 응용·포섭을 연습**하고, **SRS due 약점은 선택형으로 retention**을 점검한다. (논점이 통합된 뒤라야 사례형이 의미가 있으므로 진도 트랙과 분리.)

### 2-A. 사례형 드릴 (포섭 검토 강화 — 이 트랙의 핵심)

**사례 출제·채점 소스 우선순위**: `sync/위키/사례/{과목}/{사례}.md`(#50-B 사례층, 5섹션: 문제·풀이순서·포섭격자·모범답안·채점포인트) → `6.진도관리/사례답안/`(사용자 업로드 답안) → `case_problem_answer_index.json`. 사례노트가 있으면 거기서 문제·채점 소스를 읽는다(모범답안은 채점 시에만 노출 금지 구간 준수).

사용자 동선: **사례 답안을 `6.진도관리/사례답안/`에 저장(또는 채팅 첨부) → "올렸어"**.

1. `drill_session.json`의 `사례대기`(인박스 최신 파일) 또는 인박스를 다시 확인:
   ```powershell
   python .agent/skills/daily-drill/scripts/build_session.py --n 3   # 사례대기 갱신
   ```
   채팅에 직접 첨부했으면 그 내용을 본문으로 사용.
2. 가장 최근 답안 파일을 확정(여러 개면 사용자에게 어느 것인지 1줄 확인). 답안이 없으면 **사례노트 우선으로 사례 문제를 고른다**: ①`sync/위키/사례/{과목}/`에 해당 논점 연결 사례노트가 있으면 그 `## 문제` 섹션에서 출제(모범답안 섹션은 채점 시에만 읽음). ②사례노트 없으면 `drill_session.json`의 `복습논점[].사례문제`(=build_session가 회독≥1 논점 frontmatter 키 `과목|대분류|논점`으로 `case_problem_answer_index.json`을 조인한 결과)에서 선택. 비어 있으면(`사례[미연결]`) `book_markers`로 사례형 책 OCR에서 문제/답 span을 찾아 `problems[]`에 append하고 **`진도매핑`에 해당 논점 키(`과목|대분류|논점`)를 달아** 다음부터 자동 연결되게 한다. 출제 시 **문제(question span)만 제시**하고, **답안(answer span)은 사용자가 풀어 올린 뒤 채점 때만** 읽는다(미리 노출 금지). 문제↔답·논점은 항상 **같은 책 원문**으로 연결(#25·#40).
3. **case-answer-review 스킬로 채점**(중복 구현 금지 — 그 스킬을 호출):
   ```powershell
   python .agent/skills/case-answer-review/scripts/render_case_answer_review.py "<답안경로>" --subject <과목> --topic <쟁점> --output "E:\법학볼트\6.진도관리\사례답안\_채점_<날짜>.md"
   # 질문지·모범답안·해설 텍스트가 있으면 --question-text/--model-answer-text/--explanation-text 추가
   ```
4. 루브릭(case-answer-review SKILL의 가중표: 쟁점0.25·키워드0.20·구조0.20·결론0.15·포섭0.20)으로 평가하되, **포섭(사실↔법리 연결)을 별도 단계로 명시 점검**한다:
   - 답안의 각 법리 진술에 사건의 **구체적 사실**이 붙어 있는가(사실 없는 법리 나열이면 포섭 최대 0.5).
   - **핵심사실**(쟁점을 가르는 사실)을 빠뜨리지 않았는가(누락 시 최대 0.6).
   - 사실→요건 충족/불충족 판단→결론의 연결고리가 끊기지 않았는가.
   - **과목별 구조** 준수(case-answer-review '과목별 구조 기준' 표): 민법 다툼형=IRAC #24+#32 원고|피고 2열, 민법 검토형=설문별 IRAC, 형법=구성요건→위법성→책임·학설·죄수, 헌법=적법요건→본안. #32 2열은 민법 다툼형에만 적용(형법·헌법 강제 금지).
   질문지/모범답안 없으면 **초벌 평가**로만 표기. 감점·누락 단정에는 반드시 출처(파일·위치)를 남긴다(#1·#2).
5. 결과 약점 → Phase 3 SRS 등록 제안. 조문·사건번호는 `law_api.py verify-text`로 대조(있을 때).

원본 답안 파일은 채점 후에도 보존(이동·삭제 금지 #16). 채점 결과는 `6.진도관리/사례답안/_채점_*.md`.

### 2-A-후속. 채점 누락 → 카드 즉석 연동·약점 포섭카드 생성 (2026-07-04)

사례형 채점(G2/G3)에서 **판례 문구·키워드 누락**이 확인되면:
1. **즉석 재출제**: 그 판례·키워드를 담은 기존 카드를 찾아(`outputs/02_cards_v37/` 주제::·본문 Grep, 포섭트리거_ 포함) 그 자리에서 2~3문 풀게 한다(오답 직후가 정착 최적기).
2. **카드 부재 시 약점 포섭카드 생성**: 기존 카드·포섭사전에 해당 항목이 없으면 `outputs/02_cards_v37/약점포섭_{과목}_v37.md`에 신규 카드를 append — 형식은 포섭트리거 카드와 동일(앞=그 사례의 사실패턴, 뒤=누락한 요건/판시 연결구/결론 3-cloze), 내용은 사례노트·소스 원문에서만(#1). 태그: `단계::포섭 주제::{논점} 약점::채점누락`.
3. 약점을 mark_progress `--weak` + SRS 등록(기존 Phase 3 흐름). 약점포섭 파일은 **증분 덱 '약점'**으로 빌드되어 정본 apkg와 분리 임포트된다(#51(E) 정본 스냅샷 원칙 — 기존 카드파일 수정 금지).

### 2-A+. 포섭 역방향 드릴 (포섭사전 활용, 2026-07-03)

`sync/위키/_포섭사전/{과목}_포섭사전.md`가 있는 과목은 복습 트랙에서 **사실→규범 역방향 문제**를 섞는다: 사전의 "발동 사실패턴"만 제시 → 사용자가 발동되는 요건·규범 문구와 결론을 답 → 사전 행(판시 연결구·판례)으로 채점. 포섭 능력 자체를 훈련하는 유형(#51 far-transfer 보완).

### 2-A++. 사례비교 과제 (analogical encoding, 2026-07-07 신설)

주 1~2회(또는 사용자 요청 시), **유사 쟁점 사례노트 2건을 나란히 제시**하고(같은 쟁점 백링크·포섭사전 같은 논점의 사례들 — 예: 구분소유적 공유 무단점유 vs 공유 소수지분권자 무단임대) 사용자가 **공통 법리 구조와 결론이 갈리는 결정적 사실 차이를 한 단락으로 서술** → 두 노트의 포섭격자·모범답안으로 채점. 근거: 사례 2건 병렬 비교는 단건 분석 대비 전이를 2~3배 높인다(Loewenstein·Gentner — analogical encoding, 조사보고 §6-3). **모범답안 정독·구조 분석 단계는 상급(회독 높은) 단계에서도 생략하지 않는다**(법적 추론=비구조화 과제, 전문성 역전 미발생 — Nievelstein 2013).

### 2-B. SRS 복습 — 선택형 + 사례형 미니(2026-07-06 보강)

`drill_session.json`의 `복습due`(spaced-repetition 산출)와 `복습논점`의 약점 항목을 **선택형(객관식)으로 빠르게 복습**한다(Phase 1의 출제·채점 형식 재사용). 나간 논점이므로 정답률이 곧 retention 지표 — 떨어진 항목은 Phase 3에서 SRS 간격 단축.

**사례형 보강**: SRS due 항목 중 **대응 사례노트(백링크 조인)가 있는 것은 선택형에 더해 사례형 미니 1문을 필수 포함** — 사례노트 포섭격자에서 한 행을 골라 "이 사실이 어느 요건에 포섭되고 증명책임은 누구에게 있는가"를 한 줄 답으로 인출시킨다(L2 장기 루프의 사례형 축 — 전이 훈련). 시험모드 D-14 사례억제 시에는 생략. 소스 없는 항목은 선택형만(#1).

## Phase 3 — 마감 (기록 + 복습 연동)

```powershell
python .agent/skills/daily-drill/scripts/log_result.py ^
  --units "민법|민법총설|신의칙,민법|물권관계|점유권" ^
  --mc "9/12" --case "0.7" ^
  --weak "권리남용 요건;!사정변경 요건" --subject 민법 --srs ^
  --pass "선택"
  # --weak 항목 접두 "!" = 고확신 오답(확신했는데 틀림) → SRS priority high 등록(P0-3)
  # 문항 단위: --items '[{"unit":"민법|채권법|경개","q":"세트-성립요건","ok":1,"sub":"3/3","conf":"!","phase":"블록"}]'
  #   conf: "!"=확신 / "?"=불확신 / ""=중립  ·  phase: "블록" | "혼합"(§3-B 세션 3스텝 성취게이트 판정근거)
```

- `--units`에는 진도(선택형)·복습(사례형) 논점을 모두 기록한다(`과목|대분류|논점` 키 형식, #50-A).
- **카운트 규칙(근거 2026-06-22, `9.작업중/클로드/FSRS최적성_읽기카운트_약점재순환_연구_2026-06-22.md`):**
  - **세션당 자동 +1 폐지.** 보드 선택/사례 카운트는 그 논점 **'전체 집합'을 '기준충족 인출'한 한 바퀴**를 완료했을 때만 `--pass "선택"`/`--pass "사례"`로 올린다. 부분 세션은 `drill_log`에만 기록(카운트 X). → 사용자에게 "이 논점 한 바퀴 다 돌았어?"를 확인하고 확정 시에만 `--pass`.
  - **'1패스 완료' = 정답 인출 1회를 간격 둔 ~3세션에 걸쳐 재충족**(세션 내 3회 몰기 ❌ — 분산이 핵심).
  - **읽기(회독)는 인출과 별개·낮은 가중**: 회독은 board_server_v2/진도보드.base에서 사용자가 직접 클릭(읽기), 드릴(인출)은 선택/사례를 올린다. 회독만으로 논점 '완료' 취급 금지.
- `--srs`가 있으면 `--weak`의 각 항목을 spaced-repetition(`srs_scheduler.py --add`)에 등록(중복은 자동 병합·우선순위만 상향). **사용자가 "기록/마감"으로 확정할 때만** 등록(silent write 금지).
- **SRS 리뷰 채점 필수(2026-07-07 결선)**: 복습 트랙에서 SRS due 항목을 풀었으면 마감 시 반드시 `--srs-scores "id:score,…"`(0~5)로 채점을 넘긴다 — 이것이 SM-2 간격을 실제로 굴리는 유일한 경로다(누락 시 SRS는 등록만 되고 영원히 interval 1에 머묾). 같은 날 재채점은 1세션으로 dedup되고, **간격 둔 3세션 연속 성공 시 자동 졸업**(status=graduated, `srs_graduated_queue.jsonl`에 안키 증분덱 핸드오프 기록 + 해당 논점 `--clear-weak`).
- **문항 단위 로그(2026-07-07; conf·phase 확장 P0-3, 2026-07-14)**: 마감 시 `--items '[{"unit":"과목|대분류|논점","q":"문항 요지","ok":0|1,"sub":"n/m","conf":"!","phase":"블록"},…]'`로 문항별 정오를 `drill_items.jsonl`에 남긴다 — 3~4주 후 재출제 정답률(진짜 성과 지표)의 원천. 세트 문항은 sub에 부분점수. **conf**(`!`확신/`?`불확신/생략=중립)는 고확신 오답 탐지·메타인지 캘리브레이션용, **phase**(`블록`/`혼합`)는 §3-B 세션 3스텝의 성취 게이트(블록 정답률 과반 미달 시 혼합 제외) 판정 근거. 비표준값은 경고 후 그대로 보존.
- **약점 재순환**: 약점 논점은 다음 복습에서 **틀린 항목만이 아니라 그 논점 전체 세트를 다시 인출**한다(`build_session.py`가 약점 논점을 복습 트랙 최우선 출제 → 논점 전체 재시험). 단 **시험효과는 사례(고복잡)에선 약화** → 객관식엔 강하게, 사례엔 보수적으로.
- 기록은 `.agent/state/drill_log.jsonl`(1일 N행 허용·최신값 우선 — 트랙별 분할 기록 가능, build_session은 최신 행 기준으로 "최근 드릴" 회피 로테이션. 표현 정정 2026-07-08).
- 회독 카운트 정본(v2, #19-B): **논점 frontmatter**(`sync/위키/{과목}/{쟁점}.md`)가 정본 — 인터페이스는 `6.진도관리/board_server_v2.py`(HTML 클릭) 또는 `sync/위키/진도보드.base`(Bases 열람). 논점 1회독 끝냈으면 해당 인터페이스에서 클릭·업데이트하라고 안내한다(`progress.json` 회독을 임의로 올리지 않는다). frontmatter 회독이 0→1로 바뀌면 다음 세션부터 그 논점은 진도 트랙→복습·심화 트랙으로 이동한다.
- **논점 frontmatter 역기록(닫힌루프 보드층, #19-B)**: 드릴에서 실제 다룬 논점·약점을 `sync/위키/{과목}/{쟁점}.md` frontmatter(=논점 정본, board_server_v2·진도보드.base가 읽는 동일 소스)에 기록한다.
  ```powershell
  python .agent/skills/daily-drill/scripts/mark_progress.py --notes "민법/채권자대위권,민법/대상청구권" --weak --review
  # --weak 약점:true / --clear-weak 약점:false / --read 회독+1(논점 1회독 완료 시만) / --review 최근복습=오늘
  ```
  **논점은 에이전트가 실제 출제·오답에 근거해 명시**(`과목/제목`, #50-A 키 표준 `과목|대분류|논점`). 정규식 추정 금지(#1). 약점 항목이 특정 논점에 대응하면 그 논점에 `--weak`; SRS 졸업 시 `--clear-weak`.
- **스케줄러 노브(SRS) — 마감 인식 다중 타깃**: 알고리즘보다 **목표보유율을 마감 인식으로 튜닝**이 핵심. `srs_scheduler.py`가 시험 가까울수록 SM-2 간격을 압축(시험 당일 이후엔 복습 안 잡음). **고정 단일날짜가 아니라 다중 타깃**: 내신/변시 등을 `--add-exam "내신_2-2" --subjects "민법,형법"`(날짜 생략=미정, 추후 `--add-exam "내신_2-2" --date 2026-XX-XX`로 입력)으로 담아두면, 각 약점 항목이 자기 과목에 걸린 가장 가까운 미래 시험으로 압축됨. `--list-exams`로 확인. 날짜 미정·해당 시험 없으면 순수 SM-2. (장기 FSRS는 Anki 핸드오프.)
- 끝으로 한 줄 요약: 진도(선택형 정답률) / 복습(사례 점수·SRS) / 약점 N개(→SRS) / 내일 우선 논점.
