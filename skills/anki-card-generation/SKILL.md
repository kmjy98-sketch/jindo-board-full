# SKILL: Anki Card Generation for Law Study

## 0. 목적

이 스킬은 법학 학습 자료를 Anki 카드로 변환하기 위한 규칙이다.
실행 주체에 무관하게 적용하므로(현 운영주체 Claude Web) 특정 모델 전용 명령에 의존하지 않는다.

## 1. 우선순위

카드 작업 시 다음 순서로 읽는다.

1. 루트 `CLAUDE.md` (정본. AGENTS.md = 비클로드 에이전트용 운영 기준·참고 — 충돌 시 CLAUDE.md 우선)
2. 과목별 `AGENTS.md`(참고)
3. `.agent/workflows/card-wiki-pipeline.md`
4. 이 파일
5. `docs/anki/*.md`
6. `docs/legacy/*.md`는 참고만 한다.

충돌 시 `CLAUDE.md`와 `.agent/workflows/card-wiki-pipeline.md`를 우선한다.

## 1-B. 카드 설계 — 최신연구 반영 (2026-06-21, 보고서 9.작업중/클로드/개선종합_카드SRS_룰감사_2026-06-21.md)

- **원자성(한 카드 한 사실)**: 요건·판례 holding은 원자 cloze로(근거=스케줄링 효율, '단순=쉽다'가 아님).
- **far-transfer 보완**: 사례형 포섭처럼 통합지식은 원자화만 하면 전이 약화 → 상위 **종합/IRAC 카드 병행**(원자 cloze + 종합 카드).
- **간섭 최소화**: 유사·혼동 요건/판례(인접 법리)에는 카드에 **명시적 대조·판별 단서**를 넣는다(성숙 컬렉션 망각 최대원인=간섭).
- **LLM 생성 카드 검수 필수(human-in-loop)**: 자동생성 카드는 12결함(환각·답 힌트누출·중복보기·모호정답 등) → 배포 전 사람이 검수·수정. 미검토 대량배포 금지.
- 인라인 `주제::`는 grep 계약이라 유지하되, Obsidian Bases 대비 YAML frontmatter 병기 권장.

## 2. 입력

허용 입력:

- `sync/위키/{과목}/*.md` — 쟁점(논점) 위키 정본 (#50-B. 과목 풀네임 사용: 민사소송법·민사집행법·형사소송법 등 — 약칭 금지)
- 사용자가 직접 제공한 위키 또는 노트 텍스트
- 검증된 카드 소스
- OCR 원문(`outputs/01_ocr_llamaparse/`)에서 확인한 발췌
- `law_api.py`(법제처 직접 API) 또는 공적 법령 및 판례 원문 확인 결과

폐기 경로 (참조 금지):

- `sync/wiki/쟁점/` — #50-B로 폐기. 잔존 파일은 과목 폴더로 이관 대기 중

주의:

- `outputs/02_cards_v37/*.md`는 대량 산출물이므로 Git에 기본 포함하지 않는다.
- 워크스페이스에서 해당 파일을 읽지 못하면 Drive 자료 요청으로 처리한다.
- 원문 또는 근거가 없는 법리 단정은 만들지 않는다.

## 3. 출력

기본 출력은 Markdown 카드 초안이다.

Basic 카드:

```text
카드유형: Basic
Front:
Back:
태그:
출처:
검증상태:
```

Cloze 카드:

```text
카드유형: Cloze
Text:
Extra:
태그:
출처:
검증상태:
```

## 4. 카드 유형 (#51 3역할 체계)

카드는 역할 기준 세 가지로 분류한다. 안키(v37 apkg) 수록 = **역할①+②만**. 역할③(사례전문)은 카드화 비대상.

### 4.1 역할① A 실질 atom

논점노트(`sync/위키/{과목}/*.md`)에서 **전수 카드화·누락0 게이트** 적용 대상.

하위 분류:

- **룰 카드**: 요건, 효과, 법리 일반론. 원자 1카드 1인출.
  - 요건이 여러 개면 cloze 분할 우선.
  - 조문번호 있으면 정확히 표시. 원문 없으면 `조문 원문 미확인`.
- **판례 카드**: 판례 법리.
  - 사건번호+선고일 확인 시만 anchor 확정. 불명확 시 `[불명확]`.
  - 판례 요지를 압축해 새 법리를 창작하지 않는다.
- **조문 카드**: 조문 원문·번호. anchor는 `law_api.py`로 검증.
- **표/도해 카드**: 비교표·요건 일람. 행 단위 원자화.

메타축(태그 §5 참조):
- `단계::` — 쟁점/규범/포섭/결론 중 해당 단계 명시.
- `증명책임::` — 원고/피고(법률요건분류설 기준). 대응 항변 명시.

강조 신호: OCR 볼드·밑줄 = 해당 원자 카드의 핵심·우선순위 태그 표시 신호(별도 카드 양산 금지, 기존 원자에 흡수).

### 4.2 역할② 풀이순서 카드

사례노트(`sync/위키/사례/{과목}/*.md`)의 `## 풀이순서` 섹션만 cloze 처리.

- 절차 통목차(청구→항변→재항변 골격) 암기용.
- 사례 내용(사실관계·포섭격자·모범답안)은 포함하지 않는다.
- 1사례 노트 = 1풀이순서 카드 (분할 금지).

### 4.3 역할③ 사례 전문 (카드화 비대상)

사례 전문(`## 포섭격자`, 사실관계, 모범답안)은 안키 카드화하지 않는다.

- far-transfer 자산으로 별도 관리: 격리 채점·드릴(case-answer-review).
- 카드감사(cardaudit) 사례 누락은 누락0 게이트 면제(보고만).
- 모범답안은 채점 시에만 read.

### 4.4 MCQ/OX 카드 (선택)

객관식 및 OX 판단을 묻는다.

- 정오 근거가 있는 경우만 생성한다.
- `기출` 또는 `빈출` 태그는 소스에 명시된 경우만 붙인다.
- 해설 없는 단순 OX는 검증필요로 둔다.

## 5. 태그 체계

태그는 최소한 다음 축을 유지한다.

```text
과목::
속성::
주제::
단계::
증명책임::
출처::
검증::
```

태그 값 규칙:
- `과목::` — 풀네임 사용(민사소송법·민사집행법·형사소송법·형법총론·형법각론·민법·헌법·행정법 등). 약칭(민소법·민집법) 금지.
- `단계::` — 쟁점/규범/포섭/결론 중 하나. 역할① A카드에 필수.
- `증명책임::` — 원고/피고. 증명책임이 명확한 카드에만 부여(법률요건분류설 기준).

예시:

```text
과목::민사소송법
속성::판례
주제::기판력
단계::규범
증명책임::원고
출처::송영곤_쟁점노트
검증::anchor확인
```

금지:

- 출처 없는 `기출`
- 출처 없는 `빈출`
- 근거 없는 난이도 태그
- 모델 추정 태그
- 과목 약칭 태그(민소법·민집법 등)

## 6. 근거 규칙

모든 법리, 조문, 판례 단정은 근거를 붙인다.

```text
근거 발췌: "..."
근거 위치: 문서명 / 페이지 / 절 / chunk_id
```

위치가 없으면 다음처럼 표시한다.

```text
근거 위치: 확인 불가 - 위치 식별자 부족
```

근거가 없으면 카드를 만들지 말고 다음처럼 출력한다.

```text
자료 부족 - 카드 생성 보류
사유:
필요한 추가 자료:
```

## 7. 검증 상태

카드마다 하나의 검증 상태를 붙인다.

```text
검증::완료
검증::anchor확인
검증::원문확인필요
검증::판례확인필요
검증::조문확인필요
검증::보류
```

## 7-B. 누락0 게이트·암기장 선참고·카드파일명 (#51 정합)

### 누락0 게이트 마커

논점노트의 **전수 카드화 완료** 기준 마커:

```text
카드검증: 완료 (누락0, YYYY-MM-DD)
```

- 논점노트 frontmatter 또는 본문 하단에 기입한다.
- **`카드감사: 완료 (누락 N건…)`와 혼동 금지**: 카드감사=누락 탐지(감사) 완료 마커, 카드검증=생성·보충 완료 마커.
- 재개 시 skip·집계 기준은 오직 `카드검증` 마커로 판단한다(`카드감사:완료` 오기 금지).
- 1축이라도 미달(역할① 누락, 태그축 누락, 암기장 선확인 미수행)이면 마커 부여 금지.

### 암기장 선참고 (중복방지·필수)

카드 생성·보충 전 반드시 다음 순서를 따른다.

1. 대상 논점노트의 대응 암기장 파일(`outputs/02_cards_v37/*_암기장_v37.md` 또는 `*_v37.md`)을 glob으로 실파일 확인 후 먼저 읽는다.
2. 이미 카드화·압축된 원자는 재사용·중복 제거한다.
3. **카드감사 누락목록 기반 누락분만 보충**한다. 전체 재생성 금지.

### 카드파일명 규약

```text
outputs/02_cards_v37/{책}_llamaparse_p{페이지범위}_암기장_v37.md
```

- `{책}`: 논점노트 frontmatter의 `원문` 키에서 `outputs/01_ocr_llamaparse/{책}_llamaparse_p{범위}.md` 대응 값을 추출한다.
- 파일명에 `_llamaparse_` 포함 필수.
- 파일명에 `_암기장_v37` 또는 `_v37` 포함 필수.
- glob으로 실파일 존재 확인 후 append. 없으면 신규 생성.

### build_v37_apkg 연동

카드 파일을 빌더(`build_v37_apkg.py`)에 넘기기 전 **태그줄(`tags:` 헤더 행)을 흡수 처리**하도록 빌더가 수정된 상태(2026-06-28 이후). 태그줄이 카드 본문에 섞여도 파서가 자동 제거·분리한다. 카드 생성 시 별도 전처리 불요.

## note_key·카드 생명주기·중복방지 (card-wiki-pipeline.md §8 준수)
세부 규칙의 단일 출처는 `.agent/workflows/card-wiki-pipeline.md` §8이며 여기서 재정의하지 않는다.
- note_key: 형식 `{key}::{card_type}::{seq}`. 내용이 바뀌어도 note_key를 변경하지 않고 같은 키로 갱신한다(§8.1).
- 빌더(build_v37_apkg.py)는 genanki guid를 안정 note_key 기반(`{파일stem}::{basic|cloze}::{seq:04d}`)으로 생성하므로(2026-06-16 전환·검증 완료) 카드 텍스트 수정 시 재임포트하면 복습이력을 보존한 채 동일 노트가 업데이트된다.
- 생명주기: draft→pending→approved→batched→exported→updated, 분기 suspended/rejected. rejected는 사용자 명시 허가 없이 재생성 금지(§8.2).
- 중복방지(생성 전 순서): ①같은 note_key 존재 시 신규 생성 금지·갱신 ②같은 key+card_type+정규화 앞면 존재 시 병합 ③이미 exported면 기존을 updated로 ④rejected였던 것은 재생성 금지(§8.3).

## 8. 금지

- 교재 원문 없는 법리 창작

- 선고일 추측
- 원문에 없는 예외 창작
- 특정 모델 전용 실행 명령을 필수 경로로 작성
- 대량 `outputs` 자동 커밋
- `.apkg` Git 커밋
- 개인 학습 상태 Git 커밋
- API key 또는 MCP 실설정 커밋

## 9. apkg 빌드

apkg 빌드는 사용자가 명시 요청하거나 카드 파일을 변경한 경우에만 한다.

빌드 전 확인:

```text
- 변경된 카드 파일 목록
- 총 카드 수 예상
- Basic/Cloze 수
- 한자 잔존 여부
- 번호 없는 cloze 여부
- 과목별 분리 여부
- note_key 부여·중복 여부(card-wiki-pipeline §8.3)
```

빌드 후 확인:

```text
- 총 카드 수
- Basic/Cloze 수
- 과목별 apkg 존재 여부
- 한자 잔존 0
- 번호 없는 cloze 0
```

## 10. 접근 실패 대응

카드 생성에 필요한 원문, 기존 카드, 위키 파일을 읽지 못하면 다음 형식으로 보고한다.

```text
읽기 실패:
- 대상:
- 필요한 이유:
- 시도한 경로:
- 실패 결과:
- 후속 요청:
```

추측으로 대체하지 않는다.
